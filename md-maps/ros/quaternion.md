# 2.四元数

对于 3D 开发者（尤其是像你这样在 **Unity**、**Blender** 和 **ROS 2** 之间切换的 C++ 工程师）来说，四元数（Quaternion）是绕不开的。

虽然欧拉角（Roll/Pitch/Yaw）符合人类直觉，但在计算机图形学和机器人运动学中，四元数才是“一等公民”。

---

### 1. 为什么一定要用四元数？（痛点解决）

作为资深开发者，你一定知道欧拉角的局限性：

* **万向节死锁 (Gimbal Lock)：** 当 Pitch 角达到 $\pm$90° 时，会丢失一个自由度。
* **插值困难：** 欧拉角做平滑旋转插值（SLERP）非常生硬。
* **计算开销：** 频繁的三角函数计算比四元数的代数运算慢。

**四元数完美解决了这些问题。** 它在四维空间中表示旋转，虽然不可直观想象，但数学上极度优雅。

---

### 2. 四元数的数学结构

一个四元数通常表示为 $q = (x, y, z, w)$ 或 $q = w + xi + yj + zk$。

* **单位四元数：** 所有的旋转必须是单位四元数，即 $\sqrt{x^2 + y^2 + z^2 + w^2} = 1$。
* **几何意义：** 它可以看作是绕着一个单位向量轴 $\vec{u}(u_x, u_y, u_z)$ 旋转了 $\theta$ 角度：

$$w = \cos(\theta/2)$$


$$x = u_x \sin(\theta/2)$$


$$y = u_y \sin(\theta/2)$$


$$z = u_z \sin(\theta/2)$$



---

### 3. 不同环境下的四元数（Abner 避坑指南）

这是你作为跨平台开发者最容易出错的地方，因为**不同软件对四元数的定义和存储顺序不同**：

#### **A. 存储顺序 (Memory Layout)**

* **ROS 2 / C++ (tf2/Eigen):** 顺序通常是 **$(x, y, z, w)$**。
* **Unity (C#):** 顺序也是 **$(x, y, z, w)$**。
* **WPF / 一些数学库:** 可能是 **$(w, x, y, z)$**。

> **注意：** 在调用 API 前，务必检查 $w$ 是在首位还是末位！

#### **B. 坐标系 (Coordinate System)**

* **ROS 2:** 右手系，Z轴向上（右手定则）。
* **Unity:** **左手系**，Y轴向上。
* **转换逻辑：** 将模型从 Unity 导入 ROS 2 仿真（如 Gazebo）时，不仅要处理旋转，还要处理左右手系的镜像转换。

---

### 4. C++ 实战：在 ROS 2 中处理四元数

在 ROS 2 中，由于你有 C++ 经验，建议直接使用 `tf2` 库，它封装了复杂的数学运算。

**欧拉角转四元数 (C++):**

```cpp
#include <tf2/LinearMath/Quaternion.h>

tf2::Quaternion q;
// 输入 Roll, Pitch, Yaw (弧度)
q.setRPY(0, 0, 1.57); 

// 获取数据
double x = q.x();
double w = q.w();

```

**四元数插值 (SLERP):**
如果你在做机器人平滑转向，直接使用 `slerp`：

```cpp
// t 范围从 0 到 1
tf2::Quaternion interpolated_q = q1.slerp(q2, t);

```

### 5. 调试神器：3d-rotation-converter

既然你刚刚安装了 `mrpt-apps`，请务必利用好这个工具。它可以让你实时看到：

1. 输入一个 **$(x, y, z, w)$**。
2. 立即看到它对应的**旋转矩阵**。
3. 看到它在 **3D 空间中的指向**。

这对于调试“为什么我的机器人头朝下翻转了”这种问题效率极高。

### 总结建议

作为 C++ 开发者，**不要试图去手写四元数的乘法公式**（容易写错共轭逻辑）。

* **底层：** 信任 `Eigen::Quaterniond` 或 `tf2::Quaternion`。
* **交互：** 与 Unity 通信时，手动检查并转换坐标系。
* **校验：** 永远记住，旋转 $q$ 和 $-q$ 表示的是同一个物理姿态。

# 3.四元数几何意义： 看作是绕着一个单位向量轴 $\vec{u}(u_x, u_y, u_z)$ 旋转了 $\theta$ 角度，这个好抽象，$\theta$ 角度 是隐含的？

这种“抽象感”非常正常。对于习惯了直观坐标系的开发者来说，四元数最反直觉的地方就在于：**它把“旋转轴”和“旋转角度”揉碎了，混合存储在四个实数里。**

你说得对，$\theta$ 是**隐含**在四个分量之中的。为了让你不再觉得它抽象，我们可以用 C++ 程序员熟悉的“编码与解码”视角来拆解它。

---

### 1. 把它看作一种“数据压缩打包”

想象你要通过网络发送一个旋转指令。你有两个原始数据：

1. **方向向量 $\vec{u}$**（比如：`0, 0, 1` 表示绕 Z 轴转）。
2. **标量角度 $\theta$**（比如：`90°`）。

四元数 $q(x, y, z, w)$ 就是这一套数据的**特定编码格式**。

#### **编码公式（打包过程）：**

* $w = \cos(\frac{\theta}{2})$
* $x = u_x \cdot \sin(\frac{\theta}{2})$
* $y = u_y \cdot \sin(\frac{\theta}{2})$
* $z = u_z \cdot \sin(\frac{\theta}{2})$

**为什么不直接传轴和角？**
因为直接用轴角做旋转合成（两次连续旋转）的数学极其复杂。而编码成四元数后，两次旋转的叠加只需一次**四元数乘法**。

---

### 2. 为什么是 $\frac{\theta}{2}$ ？（隐含的精妙之处）

这是最容易让人困惑的地方。为什么不是 $\cos(\theta)$？

* **数学原因：** 旋转本质上是一种算子。为了让四元数乘法 $q v q^{-1}$ 能够正确工作，数学上必须使用半角。
* **直观结果：** 这导致了一个神奇的现象——**双倍覆盖（Double Cover）**。
* 如果你把 $\theta$ 设为 $360^\circ$，代入公式：$w = \cos(180^\circ) = -1$，$x,y,z = 0$。
* 如果你把 $\theta$ 设为 $0^\circ$，代入公式：$w = \cos(0^\circ) = 1$，$x,y,z = 0$。
* **物理意义：** 虽然转 $360^\circ$ 和不转在空间姿态上是一样的，但在四元数里，$q$ 和 $-q$ 代表了不同的旋转路径。



---

### 3. 如何从四元数里“逆推”出角度 $\theta$？

既然 $\theta$ 是隐含的，作为 C++ 开发者，我们可以写一个逻辑上的“解码器”：

如果我们拿到了一个单位四元数 $(x, y, z, w)$，你可以瞬间反推出旋转了多少度：


$$\theta = 2 \cdot \arccos(w)$$

* 如果 $w = 1$，说明 $\arccos(1) = 0$，所以 $\theta = 0^\circ$（没转）。
* 如果 $w = 0.707$（即 $\frac{\sqrt{2}}{2}$），说明 $\arccos(0.707) = 45^\circ$，所以 $\theta = 90^\circ$。
* 如果 $w = 0$，说明 $\arccos(0) = 90^\circ$，所以 $\theta = 180^\circ$。

---

### 4. 举个具体的例子（从抽象到具体）

假设你想要机器人绕着 **Y 轴**（在 ROS 2 中通常是左侧方向）旋转 **90°**。

1. **确定轴 $\vec{u}$：** $(0, 1, 0)$
2. **确定角 $\theta$：** $90^\circ$（即 $\pi/2$ 弧度）。
3. **计算分量：**
* $\theta/2 = 45^\circ$
* $w = \cos(45^\circ) = 0.707$
* $x = 0 \cdot \sin(45^\circ) = 0$
* $y = 1 \cdot \sin(45^\circ) = 0.707$
* $z = 0 \cdot \sin(45^\circ) = 0$


4. **最终四元数：** $(0, 0.707, 0, 0.707)$ —— 看到没？$\theta$ 已经完全消融在 $w$ 和 $y$ 里面了。

---

### 5. 资深开发者的直观结论

在 debug 时，你可以盯着 $w$ 分量看：

* **$w$ 越接近 1**，旋转角度越小。
* **$w$ 越接近 0**，旋转角度越接近 $180^\circ$。
* **$x, y, z$ 的比例**，直接告诉你旋转轴指向哪里。

**既然你现在手边有 `3d-rotation-converter`：**
试着在 GUI 里把 $w$ 从 1 慢慢拉到 0，你会发现 3D 窗口里的物体非常顺滑地从 0° 转到了 180°。这种“隐含”的角度感，通过几次动手操作就会变成你的直觉了。

这种“打包”方式对你处理复杂的 3D 场景（比如多关节机械臂）极其有利，因为无论旋转多复杂，内存里永远只有 4 个 `double`。

# 4.四元数 的 乘法

对于 C++ 开发者来说，理解四元数乘法的最佳方式是：**不要把它当成普通的乘法，而要把它看作是“变换的复合（Composition）”**。

在机器人开发中，如果你有两个连续的旋转 $q_1$ 和 $q_2$，那么总的旋转就是 $q = q_2 \otimes q_1$。

---

### 1. 核心数学公式

假设有两个四元数：
$q_1 = (w_1, v_1)$ 其中 $v_1 = (x_1, y_1, z_1)$ 是向量部分
$q_2 = (w_2, v_2)$ 其中 $v_2 = (x_2, y_2, z_2)$ 是向量部分

它们的乘积 $q = q_2 \otimes q_1$ 的结果为：

* **标量部分 ($w$)：** $w = w_2w_1 - v_2 \cdot v_1$
* **向量部分 ($v$)：** $v = w_2v_1 + w_1v_2 + v_2 \times v_1$

> **注意那个叉乘 ($v_2 \times v_1$)！**
> 既然有叉乘，就意味着 **$q_2 \otimes q_1 \neq q_1 \otimes q_2$**。四元数乘法不满足交换律，这和矩阵乘法是一样的。

---

### 2. 物理意义：旋转的累加

这是你作为开发者最常用到的逻辑：

* 如果你有一个姿态 $q_{base}$（机器人当前朝向）。
* 你产生了一个相对旋转 $q_{rotate}$（比如左转 30 度）。
* **最终姿态** $q_{new} = q_{rotate} \otimes q_{base}$。

**顺序原则：**

* **左乘 ($q_{rotate} \otimes q_{base}$)**：相对于全局坐标系（世界系）旋转。
* **右乘 ($q_{base} \otimes q_{rotate}$)**：相对于**自身局部坐标系**旋转（这是在机器人运动控制中最常见的场景）。

---

### 3. C++ 代码实战（避免手写公式）

虽然公式看起来复杂，但在 C++ 开发中，我们永远推荐使用成熟的库，因为它们处理了所有的浮点精度和归一化问题。

#### **使用 Eigen (最常用):**

如果你在做 3D 重建或视觉算法，Eigen 是首选。

```cpp
#include <Eigen/Geometry>

Eigen::Quaterniond q1(w1, x1, y1, z1); // 注意 Eigen 的构造函数顺序是 (w, x, y, z)
Eigen::Quaterniond q2(w2, x2, y2, z2);

// 复合旋转：先转 q1，再转 q2
Eigen::Quaterniond q_total = q2 * q1; 

// 归一化（防止舍入误差累积导致四元数失效）
q_total.normalize();

```

#### **使用 ROS 2 tf2:**

如果你在写 ROS 2 节点：

```cpp
#include <tf2/LinearMath/Quaternion.h>

tf2::Quaternion q1, q2;
// ... 初始化 q1, q2 ...

// tf2 重载了 * 运算符
tf2::Quaternion q_total = q2 * q1; 

```

---

### 4. 关键避坑点

1. **归一化 (Normalization)：**
由于浮点数运算误差，多次乘法后四元数的模长可能不再等于 1。在循环执行旋转累加时，**务必每隔几次运算就调用一次 `normalize()**`。如果不归一化，你的 3D 模型会产生莫名的形变（在视觉上可能会看到模型变大或变小）。
2. **求逆 = 共轭：**
在单位四元数中，逆旋转 $q^{-1}$ 等于共轭四元数 $q^*$（即把 $x, y, z$ 取反）。
* $q = (w, x, y, z)$
* $q^{-1} = (w, -x, -y, -z)$
这在计算“相对旋转”时非常有用：$q_{relative} = q_{target} \otimes q_{current}^{-1}$。


3. **计算顺序：**
如果你发现旋转的方向反了，90% 的概率是乘法顺序写反了（$q_1 \otimes q_2$ vs $q_2 \otimes q_1$）。

### 总结

四元数乘法就是**旋转的叠加**。既然你习惯了 C++，只需记住：

* **`*` 运算符**在库里已经重载好了。
* **顺序很重要**（通常是右乘局部，左乘全局）。
* **定期归一化**是保持系统稳定的关键。
