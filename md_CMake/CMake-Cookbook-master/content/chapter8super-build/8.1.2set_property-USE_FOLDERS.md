# 1.set_property(GLOBAL PROPERTY USE_FOLDERS ON)

在 CMake 中，`set_property(GLOBAL PROPERTY USE_FOLDERS ON)` 是一个用于**启用 IDE 文件夹组织功能**的全局配置，主要作用是让生成的项目在支持文件夹结构的 IDE（如 Visual Studio、Xcode、Qt Creator 等）中，以逻辑文件夹的形式归类目标（库、可执行文件等），使项目结构更清晰。


### 核心作用
- **开启文件夹支持**：告诉 CMake 生成项目文件时，保留目标的文件夹属性（通过 `FOLDER` 属性设置的归类信息）。
- **影响范围**：全局生效，所有后续定义的目标（`add_library`/`add_executable`）的 `FOLDER` 属性都会被 IDE 识别。


### 用法场景
当项目包含多个目标（如多个库、工具、插件）时，通过以下组合可以实现 IDE 中的文件夹归类：

1. 首先开启文件夹支持：
   ```cmake
   # 全局启用文件夹功能（通常放在 CMakeLists.txt 开头）
   set_property(GLOBAL PROPERTY USE_FOLDERS ON)
   ```

2. 为目标设置具体文件夹（配合 `SET_TARGET_PROPERTIES`）：
   ```cmake
   # 定义目标
   add_library(plugin1 SHARED src/plugin1.cpp)
   add_library(plugin2 SHARED src/plugin2.cpp)
   add_executable(myapp src/main.cpp)

   # 归类到不同文件夹
   set_target_properties(plugin1 PROPERTIES FOLDER "Plugins")
   set_target_properties(plugin2 PROPERTIES FOLDER "Plugins")
   set_target_properties(myapp PROPERTIES FOLDER "Applications")
   ```

3. 在 IDE 中会显示：
   - 一个 `Plugins` 文件夹，包含 `plugin1`、`plugin2` 两个目标
   - 一个 `Applications` 文件夹，包含 `myapp` 目标


### 注意事项
- **IDE 兼容性**：仅对支持文件夹结构的 IDE 有效（如 Visual Studio、Xcode），对命令行编译（如 Makefile、Ninja）无影响。
- **默认关闭**：CMake 默认 `USE_FOLDERS` 为 `OFF`，此时即使设置了 `FOLDER` 属性，IDE 也不会创建文件夹，所有目标会平铺显示。
- **嵌套文件夹**：支持通过 `/` 或 `\` 定义嵌套结构，例如 `FOLDER "Plugins/ImageFormats"` 会创建 `Plugins` 父文件夹，其中包含 `ImageFormats` 子文件夹。


### 总结
`set_property(GLOBAL PROPERTY USE_FOLDERS ON)` 是组织大型 CMake 项目的实用配置，通过与 `FOLDER` 目标属性配合，能在 IDE 中清晰展示项目结构，提升开发效率。
