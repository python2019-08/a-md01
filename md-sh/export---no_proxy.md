# 1.no_proxy如何设置

`no_proxy` 是一个环境变量，用于指定不需要通过代理服务器访问的主机或域名。在处理本地网络连接问题时，正确设置 `no_proxy` 可以避免请求被错误地路由到代理服务器。

### 不同操作系统的设置方法

#### Linux/macOS

在终端中临时设置：
```bash
export no_proxy="localhost,127.0.0.1,::1"
```

永久设置（对所有终端会话生效）：
1. 编辑 `~/.bashrc` 或 `~/.zshrc` 文件：
   ```bash
   echo 'export no_proxy="localhost,127.0.0.1,::1"' >> ~/.bashrc
   ```
2. 使配置生效：
   ```bash
   source ~/.bashrc
   ```

#### Windows

在命令提示符中临时设置：
```batch
set no_proxy=localhost,127.0.0.1
```

在PowerShell中临时设置：
```powershell
$env:no_proxy = "localhost,127.0.0.1"
```

永久设置（系统级别）：
1. 打开"系统属性" > "高级系统设置" > "环境变量"
2. 在"系统变量"中添加或编辑 `no_proxy` 变量
3. 值设置为：`localhost,127.0.0.1`

### 设置多个条目

`no_proxy` 支持多个条目，用逗号分隔：
```bash
# 包含本地地址、特定域名和IP范围
export no_proxy="localhost,127.0.0.1,::1,.example.com,192.168.0.0/16"
```

### 在Python脚本中临时设置

如果你不想修改系统环境变量，可以在Python脚本中临时设置：
```python
import os
import httpx

# 设置环境变量
os.environ["no_proxy"] = "localhost,127.0.0.1"

# 现在发出的请求将跳过代理
response = httpx.get("http://127.0.0.1:8978")
```

### 验证设置是否生效

使用 `curl` 测试：
```bash
curl -v http://localhost:8978
```

在输出中查找类似以下内容，确认没有使用代理：
```
*   Trying 127.0.0.1:8978...
```

如果看到类似以下内容，则表示仍在使用代理：
```
*   Trying proxy-server-ip:port...
```

### 常见问题

1. **大小写敏感**：在Linux/macOS中，`NO_PROXY` 和 `no_proxy` 是不同的变量，而在Windows中不区分大小写。

2. **通配符支持**：部分系统支持通配符，例如 `.example.com` 表示所有以 `example.com` 结尾的域名。

3. **与HTTP_PROXY的关系**：如果同时设置了 `HTTP_PROXY` 和 `no_proxy`，请求会根据 `no_proxy` 的规则决定是否绕过代理。

如果你的网络环境复杂，建议直接在代码中使用 `httpx` 的代理设置，这样更明确：
```python
client = httpx.Client(proxies={
    "http://": None,  # 不使用代理
    "https://": None,
})
response = client.get("http://127.0.0.1:8978")
```

# 2.这里::1是什么意思

`::1` 是**IPv6 本地回环地址**，功能与 IPv4 中的 `127.0.0.1` 类似，用于标识本地计算机自身。它属于 IPv6 地址中的特殊保留地址，全称是 `0:0:0:0:0:0:0:1`，通常缩写为 `::1`。


### 详细解析
1. **IPv6 地址格式**  
   IPv6 地址由 8 组 16 进制数组成，每组用冒号分隔（如 `2001:0db8:85a3:0000:0000:8a2e:0370:7334`）。  
   连续的 `0` 组可以用双冒号 `::` 缩写，因此 `0:0:0:0:0:0:0:1` 可简化为 `::1`。

2. **与 IPv4 回环地址的对应关系**  
   - IPv4 本地回环：`127.0.0.1`（仅支持 IPv4 协议的本地通信）。  
   - IPv6 本地回环：`::1`（支持 IPv6 协议的本地通信）。  
   当系统同时支持 IPv4 和 IPv6 时，`::1` 和 `127.0.0.1` 分别用于不同协议的本地连接。

3. **应用场景**  
   - 本地开发测试：访问本地启动的服务（如 `http://[::1]:8080`）。  
   - 网络配置：在 `no_proxy` 中添加 `::1`，确保 IPv6 本地请求不经过代理。  
   - 系统文件：例如 Linux 的 `/etc/hosts` 中通常包含 `::1 localhost`，用于本地域名解析。


### 为什么在 `no_proxy` 中需要包含 `::1`？
当系统启用 IPv6 时，本地服务可能同时监听 IPv4 和 IPv6 地址。若 `no_proxy` 仅包含 `127.0.0.1`，则 IPv6 协议的本地请求（如 `::1`）仍可能被代理拦截。因此，完整的 `no_proxy` 配置通常同时包含：
- `127.0.0.1`（IPv4 本地回环）  
- `::1`（IPv6 本地回环）  
- `localhost`（域名形式的本地主机，可解析为上述地址）

示例配置：
```bash
export no_proxy="localhost,127.0.0.1,::1"
```


### 测试 `::1` 的连通性
1. **Windows**  
   ```powershell
   ping ::1
   ```

2. **Linux/macOS**  
   ```bash
   ping6 ::1
   ```

3. **浏览器访问**  
   在地址栏输入 `http://[::1]:端口`（方括号用于区分 IPv6 地址和端口号），例如 `http://[::1]:8080`。


### 总结
`::1` 是 IPv6 协议下的本地回环地址，与 IPv4 的 `127.0.0.1` 功能等价。在网络配置中同时包含两者，可确保本地服务在 IPv4 和 IPv6 环境下都能绕过代理正常访问。
